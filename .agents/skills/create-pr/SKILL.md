# Create PR

실제 PR 생성은 서브 에이전트가 담당한다. 이 스킬을 만드는 요청 자체는 PR 생성 권한이 아니다.

## 위임

메인 에이전트는 `spawn_agent`로 PR 담당 하나를 생성하고 저장소 절대 경로, 이 스킬 경로, 사용자 요청 범위, 알려진 base/head, 검증 결과, 커밋·push 권한 및 제약을 전달한다. 서브 에이전트는 이 스킬과 적용되는 AGENTS.md를 읽는다. 이미 PR 담당으로 위임받았다면 재위임하지 않는다. 메인 에이전트는 같은 브랜치를 동시에 수정하거나 별도 PR을 생성하지 않는다. 위임 도구가 없으면 준비된 문안과 제약을 반환하고 대신 게시하지 않는다.

## 서브 에이전트 작업

1. 저장소 지침, remotes, 현재 브랜치, 작업 트리, base 대비 커밋과 전체 diff를 확인한다. 대상 저장소와 base/head를 확인하고 `origin`이나 `main`으로 가정하지 않는다. 같은 head/base의 open PR이 있으면 링크를 반환한다. 수정 요청 없이 기존 PR을 덮어쓰거나 중복 생성하지 않는다.
2. 커밋되지 않은 변경은 PR에 포함되지 않음을 확인한다. 커밋 권한이 있으면 저장소 규칙을 따르고, 없으면 필요한 권한만 질문한다. 무관한 변경을 포함하거나 버리지 않는다.
3. 아래 기준으로 언어를 선택하고 해당 참조만 읽는다. 저장소에 필수 PR 양식이 있으면 그 구조와 항목을 유지하며 참조의 작성 원칙을 적용한다.
4. 최종 diff를 기준으로 문제와 변경 후 동작을 먼저 설명한다. 관련 검증을 실행하거나 동일 코드에 대한 기존 결과를 활용한다. 명령·결과·미검증 범위를 사실대로 적는다. 실제 관련 이슈만 연결하고 해결 관계가 확인된 경우에만 자동 종료 문구를 쓴다.
5. PR 생성 요청은 해당 PR 게시 권한으로 취급한다. 커밋·push 권한은 사용자 요청과 저장소 지침에서 별도로 확인한다. 필요한 push 권한이 없으면 제목·본문·대상 브랜치를 준비한 뒤 해당 권한만 질문한다. 이미 받은 권한을 다시 묻지 않는다.
6. 사용 가능한 GitHub 도구를 우선 사용하고 기능이 부족하면 `gh`를 사용한다. `gh` 본문은 작업 트리 밖 UTF-8 임시 파일에 실제 줄바꿈으로 저장해 `--body-file`로 전달한다. 생성 직전 대상 저장소, base/head와 최신 커밋을 재확인한다. 승인된 일반 push만 수행하고 force push, 이력 재작성, merge는 하지 않는다. draft는 사용자 지정과 저장소 규칙을 따르며 별도 지정이 없으면 일반 PR을 생성한다.
7. 실패·타임아웃 시 원격 PR 존재 여부를 먼저 조회한다. 미생성이 확인되고 원인이 해결된 경우에만 재시도한다. 인증·권한 문제나 동일 실패가 지속되면 문안과 차단 원인을 반환한다.
8. 생성 후 원격 URL, 제목·본문, base/head, draft 상태를 확인한다. URL, 선택 언어와 근거, 검증 결과, 남은 제약을 메인 에이전트에 반환한다. 메인 에이전트는 결과를 확인해 보고한다.

## 언어 선택

사용자가 지정한 언어가 최우선이다. 그 외에는 대상 저장소의 CONTRIBUTING, PR 템플릿, 최근 PR 본문·제목, README 순으로 기여 언어를 판단한다. 작성자 국적, 소유자 이름, 현재 대화 언어만으로 판단하지 않는다.

- 해외·국제 오픈소스 등 영문 기여가 기본이면 [영문 템플릿](references/pr-template.en.md)을 사용한다.
- 한국어 기여가 기본인 한국 프로젝트면 [한국어 템플릿](references/pr-template.ko.md)을 사용한다.
- 혼합 프로젝트는 명시적 기여 규칙을 우선하고, 근거가 없으면 README의 주 언어를 사용한다. 그것도 불명확하면 언어만 질문한다.

제목과 본문은 선택한 언어로 작성하며 코드 식별자와 명령은 원문을 유지한다.
